# セット商品管理機能 仕様書

## 概要
1回の購入で複数のコーヒー豆がセットになっている商品を管理するための機能。セット商品を親Bagとして登録し、到着後に各豆の詳細を子Bagとして追加できる。

## データモデル

### Bag インターフェースの拡張
```typescript
interface Bag {
  // 既存フィールド
  id: string;
  name: string;
  roaster: string;
  purchaseDate: string;
  roastDate?: string;
  bagWeight_g: number;
  remaining_g: number;
  bagDose_g: number;
  process?: string;
  pricePerBag_JPY?: number;
  url?: string;
  flavorNote?: string;
  consumeLogs: ConsumeLog[];

  // 新規フィールド
  isSet?: boolean;              // セット商品かどうか
  parentBagId?: string;         // 親セットのID（子Bagの場合のみ）
  childBagIds?: string[];       // 子BagのIDリスト（親Bagの場合のみ）
  setInfo?: {
    totalPriceJPY: number;      // セット全体の購入価格
    purchaseDate: string;       // セットの購入日
  };
}
```

## 機能要件

### 1. セット商品の登録（親Bag作成）

#### 登録フォーム（新規登録時）
- 既存のBag登録フォームに「セット商品」チェックボックスを追加
- チェック時、以下の項目のみ入力可能:
  - セット名（例: "ディフィニティブ 3種セット"）
  - ロースター名
  - 購入日
  - セット価格（必須）
  - URL（商品ページ）
  - メモ
- **非表示になる項目**（セット商品では不要）:
  - 袋重量（子Bagの合計値を自動表示）
  - 焙煎日
  - 価格（任意） ← セット価格のみ使用
  - プロセス
  - 品種
  - この袋の1杯量

#### 編集フォーム（既存Bagの変更）
- EditBagPageに「セット商品として登録」チェックボックスを追加
- チェックすることで既存の通常Bagをセット商品に変更可能
- チェックを外すことでセット商品を通常Bagに戻すことも可能
- セット商品に変更時、`remaining_g`は自動的に0に設定される
- 通常Bagに戻す際、`childBagIds`などセット関連プロパティは削除される
- **セット商品編集時の表示項目**:
  - セット名
  - ロースター名
  - 購入日
  - セット価格（¥・必須） ← 編集可能
  - URL（商品ページ）
  - メモ
- **編集時も新規登録時と同様に、セット商品チェック時は以下のフィールドが非表示**:
  - 袋重量 ← 編集不可、子Bagの合計値から自動計算（詳細画面で表示）
  - 現在の残量 ← 編集不可、子Bagの合計値から自動計算（一覧・詳細画面で表示）
  - 焙煎日
  - 価格（任意） ← セット価格のみ使用
  - プロセス
  - 品種
  - この袋の1杯量

#### データ設定
- `isSet = true`
- `remaining_g = 0`（消費管理は子Bagで行う）
- `childBagIds = []`（初期は空配列）
- `setInfo` にセット価格と購入日を保存

### 2. セット内容の追加（子Bag作成）

#### トリガー
- 親Bagの詳細画面に「セット内容を追加」ボタンを表示
- ボタンクリックで子Bag登録フォームを表示

#### 子Bag登録フォーム
- 通常のBag登録項目を入力
- `parentBagId` は自動設定
- 価格は以下のいずれか:
  - 手動入力
  - セット価格を子Bag数で均等割（自動計算オプション）

#### データ更新
- 子Bag作成時、親Bagの`childBagIds`配列に追加
- 子Bagに`parentBagId`を設定

### 3. 表示・一覧

#### 一覧画面
- **デフォルト**: 親Bagのみ表示、子Bagは非表示
- オプション: "セット内容も表示"フィルターで子Bagも表示可能
- 子Bagには「🔗 セットの一部」などの視覚的インジケーター
- **親Bagの残量表示**: 子Bagの`remaining_g`の合計値を表示、子Bagがない場合は「未設定」と表示

#### 詳細画面

**親Bagの場合:**
- **表示する情報:**
  - セット名
  - ロースター名（品種・プロセスは非表示）
  - 購入日
  - セット価格（setInfo.totalPriceJPY）
  - 購入グラム数（子Bagの`bagWeight_g`の合計値、子Bagがない場合は0g）
  - セット内容一覧（子Bagリスト）
    - 各子Bagの名前、残量、ピークステータス
    - 各子Bagへのリンク
  - 編集ボタン
  - 「セット内容を追加」ボタン

- **表示しない情報:**（親Bagは消費しないため）
  - 品種（variety）
  - プロセス（process）
  - 残量・杯数のカード
  - ピークステータス
  - 消費履歴
  - 1杯消費ボタン
  - 抽出を記録ボタン

**子Bagの場合:**
- 通常のBag情報を表示
- 「〇〇セットの一部」と表示し、親Bagへのリンク
- 通常通り消費管理・冷凍管理が可能

### 4. 編集・削除

#### 親Bagの削除
- 削除時に確認ダイアログを表示:
  - 「このセットには〇個の豆が含まれています。セットごと削除しますか？」
  - オプション1: セットごと削除（親・子すべて削除）
  - オプション2: セット情報のみ削除（子Bagは独立したBagとして保持）

#### 子Bagの削除
- 通常のBag削除と同様
- 親Bagの`childBagIds`から該当IDを削除

#### 編集
- 親Bag: セット情報の編集可能
- 子Bag: 通常のBag編集と同様、`parentBagId`の変更は不可

## データ整合性ルール

1. **親Bagの制約**
   - `isSet = true` の場合、`remaining_g = 0` （固定）
   - 消費ログ・冷凍ポーションは作成不可

2. **子Bagの制約**
   - `parentBagId` が設定されている場合、通常のBagとして機能
   - 親Bagが存在しない場合、`parentBagId`を削除（孤立を防ぐ）

3. **親子関係**
   - 親Bagの`childBagIds`と子Bagの`parentBagId`は常に同期
   - 多階層構造は禁止（親の親は作れない）

## UI/UX フロー

### セット商品登録フロー
```
1. ホーム画面で「新規登録」
2. 「セット商品」チェックボックスをON
3. セット情報を入力（名前、価格、購入日など）
4. 保存 → 親Bag作成完了
5. 詳細画面に遷移
6. 「セット内容を追加」ボタンで子Bagを登録
7. 各豆の詳細情報を入力
8. 保存 → 子Bag作成、親のchildBagIdsに追加
9. 繰り返し（セット内の全ての豆を登録）
```

### 通常使用フロー
```
- 一覧画面: 親Bagのみ表示（子Bagは非表示）
- 詳細画面: 子Bagには親セットへのリンクあり
- 消費・冷凍: 子Bag単位で管理
- オプション: "セット内容も表示"チェックで子Bagも一覧に表示可能
```

## 考慮事項

### データ保存
- 現状は IndexedDB（Dexie）のみ。クラウド同期は未実装
- `childBagIds`と`setInfo`はローカルの Bag レコードに保存する

### マイグレーション
- 既存データへの影響なし（新規フィールドはオプショナル）
- 既存Bagは通常通り機能

### パフォーマンス
- 親Bagから子Bagの取得: `childBagIds`を使ったバッチ取得
- 子Bagから親Bagの取得: `parentBagId`による直接取得
