# Agent TDD テンプレート

このテンプレートを使用してAgent（Task tool）にTDD実装を依頼してください。

## 基本テンプレート

```
【TDD必須】TDD三原則に従って実装してください。

## TDD三原則
1. 失敗するテストを成功させる以外の目的で実装コードを書いてはならない
2. コンパイルが通らず、失敗するテストを作る以外の目的でテストコードを書いてはならない
3. 現在失敗しているテストを成功させる以外の目的で実装コードを書いてはならない

## 実装要件
- 機能: [具体的な機能名]
- 対象ファイル: [実装ファイルパス]
- テストファイル: [テストファイルパス]

## TDDサイクル（RED → GREEN → REFACTOR）
1. **RED**: 失敗するテスト（最小限）を書く
   - まだ存在しない機能をテストする
   - コンパイルエラーや実行時エラーで失敗させる
2. **テスト実行で失敗確認**
3. **GREEN**: 仮実装で最小限にテストを通す
   - 固定値を返すなど最も簡単な実装から始める
   - テストが通ることだけを目的とする
4. **テスト実行で成功確認**
5. **REFACTOR**: 重複除去と改善
   - テストコードと実装コードの重複を除去
   - 意味のある実装に改善（必要に応じて三角測量）
6. **各ステップでテストが通ることを確認**

## ベイビーステップ原則
- 一度に追加するコードは最小限に
- 仮実装から始めて徐々に一般化
- 各ステップでテストが通ることを確認

## 完了条件
- [ ] TDD三原則に従って実装された
- [ ] テストファイルが先に作成されている
- [ ] 全テストが通る
- [ ] 実装が要件を満たす
- [ ] 重複が除去されている

実装を開始してください。
```

## 使用例

### 新機能の実装
```
【TDD必須】TDD三原則に従って、コーヒー豆の評価機能を実装してください。

## TDD三原則
1. 失敗するテストを成功させる以外の目的で実装コードを書いてはならない
2. コンパイルが通らず、失敗するテストを作る以外の目的でテストコードを書いてはならない
3. 現在失敗しているテストを成功させる以外の目的で実装コードを書いてはならない

## 実装要件
- 機能: コーヒー豆に5段階評価を追加
- 対象ファイル: src/features/rating/RatingComponent.tsx
- テストファイル: src/features/rating/__tests__/RatingComponent.test.tsx

## 機能詳細
- 1-5の星評価システム
- クリックで評価変更
- 評価の保存・表示

## TDDサイクル
1. **RED**: RatingComponent.test.tsxに失敗するテストを書く
   - まだ存在しないRatingComponentをimportする（コンパイルエラー）
2. **テスト実行で失敗確認** (npm test)
3. **GREEN**: RatingComponent.tsxで仮実装
   - 空のコンポーネントを作成してコンパイルエラーを解消
   - 固定値（例：常に3を返す）で最初のテストを通す
4. **テスト実行で成功確認**
5. **REFACTOR**: 重複除去と改善
6. **三角測量**: 異なる入力値でテストを追加し、一般化

ベイビーステップで1つの機能ずつ追加してください。
```

### 既存機能の拡張
```
【TDD必須】既存のBagコンポーネントに削除確認機能をTDDで追加してください。

## 実装要件
- 機能: 削除前の確認ダイアログ
- 対象ファイル: src/features/bag-detail/DetailPage.tsx
- テストファイル: src/features/bag-detail/__tests__/DetailPage.test.tsx（追記）

## 機能詳細
- 削除ボタンクリック時に確認ダイアログ表示
- 「はい」で削除実行、「いいえ」でキャンセル
- 既存機能への影響なし

## TDDプロセス
1. DetailPage.test.tsxに削除確認のテスト追加（失敗）
2. テスト実行で失敗確認
3. DetailPage.tsxに最小実装
4. テスト通過後にリファクタリング

実装を開始してください。
```

### バグ修正
```
【TDD必須】同期エラーのバグをTDDで修正してください。

## 実装要件
- 機能: ネットワークエラー時の適切なエラーハンドリング
- 対象ファイル: src/lib/sync/syncService.ts
- テストファイル: src/lib/sync/__tests__/syncService.test.ts（追記）

## バグ詳細
- ネットワーク障害時にアプリがクラッシュ
- エラーメッセージが表示されない
- 再試行機能が動作しない

## TDDプロセス
1. バグを再現するテストを追加（失敗）
2. テスト実行でバグ確認
3. 最小限の修正でテスト通過
4. エラーハンドリングを改善

実装を開始してください。
```

## チェックリスト

### Agent起動前
- [ ] 実装対象を明確にした
- [ ] テストファイルパスを決定した
- [ ] 「TDD必須」を指示に含めた
- [ ] 具体的な要件を記述した

### Agent作業中
- [ ] テストファイルが先に作成された
- [ ] 失敗するテストから開始した
- [ ] 最小実装でテストを通した
- [ ] 適切にリファクタリングした

### 完了時
- [ ] 全テストが通る
- [ ] 実装が要件を満たす
- [ ] コードが読みやすい
- [ ] コミット可能な状態

## よくある間違い

❌ **NG例：テスト後回し**
```
新機能を実装してください。テストも書いてください。
```

✅ **OK例：TDD明示**
```
【TDD必須】新機能をテスト駆動開発で実装してください。
まずテストファイルを作成し、失敗するテストを書いてから実装を開始してください。
```

❌ **NG例：曖昧な指示**
```
バグを修正してください。
```

✅ **OK例：具体的なTDD指示**
```
【TDD必須】バグをTDDで修正してください。
1. バグを再現するテストを先に書く
2. テスト失敗を確認
3. 最小修正でテスト通過
4. リファクタリングで品質向上
```
