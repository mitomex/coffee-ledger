# Coffee Ledger

自家用コーヒー豆の在庫と抽出記録を管理する、ローカルファーストのWebアプリケーションです。豆の残量をグラム数と「あと何杯」で確認し、購入から日々の消費までを記録できます。

公開URL: https://coffee-ledger-eta.vercel.app/

データはブラウザのIndexedDBに保存され、端末の外へは送信されません。ローカルでの起動手順は[ローカルで動かす](#ローカルで動かす)を参照してください。

## 開発背景

自分で使うコーヒー豆の管理ツールが必要だったことをきっかけに、個人で開発しました。日常で必要なアプリケーションを題材に、Claude Codeを使った開発環境を試すことも目的としています。

業務ではVue.jsを使う機会が多いため、このプロジェクトではReactを選び、実際のアプリケーション開発を通して経験を広げたいと考えました。また、AIを活用する開発環境でTDDをどのように組み込むかを検討しながら制作しています。

| 項目 | 内容 |
| --- | --- |
| 開発体制・期間 | 個人開発・約1週間 |
| 開発の進め方 | 要件定義・画面構成・仕様は自分で決定。実装はすべてClaude Code・Cursor・Codexを用いてAIで行った。 |
| 利用・確認方法 | 自分用のコーヒー豆管理ツールとして実機で実際に使用しながら、AIが実装した画面や機能の動作を確認した。 |

## 主な機能

| 機能 | できること |
| --- | --- |
| 在庫一覧 | 豆の残量・残り杯数を確認し、日付や残り杯数による並び替え、精製方法による絞り込みを行う |
| 豆の登録・編集 | 購入日、重量、価格、焙煎日、産地、画像などを記録する |
| 抽出記録 | 豆量、挽き目、湯温、湯量、メモを保存し、在庫への反映を選択する |
| セット商品 | セット全体の購入情報と、セットに含まれる個々の豆を管理する |
| 定期購入 | 購入周期を登録し、アプリ起動時に購入記録の自動作成をチェックする |
| 履歴 | 飲み切った豆や各商品の抽出記録を振り返る |

公開URLまたはローカル環境で、「豆を登録 → 在庫一覧で残量を確認 → 詳細から抽出を記録 → 更新された残量と記録を確認」の順に操作すると、基本的な利用の流れを確認できます。

## UI・体験設計

### コーヒー豆を中心としたオブジェクト指向UI

オブジェクト指向UI（OOUI）を意識し、コーヒー豆を起点に画面を構成しました。中心となる対象は、購入日・重量・残量を持つ「購入した一袋の豆」です。在庫一覧から豆を選択し、その詳細で情報を確認してから、編集や抽出記録の追加を行います。

豆の詳細には関連する抽出記録の一覧を配置し、各記録の詳細へ移動できます。セット商品では、セットの詳細から個々の豆へ、個々の豆から親セットへ移動する構成です。

実装：[豆の一覧](src/features/home/HomePage.tsx) · [豆と関連情報の詳細](src/features/bag-detail/DetailPage.tsx) · [抽出記録の詳細](src/features/bag-detail/ExtractionDetailPage.tsx)

「対象を選ぶ → 対象への操作を選ぶ」という基本構造に沿って、抽出記録の編集導線や、在庫と定期購入設定の区別を整えています。

### 残量を日常の単位で表示

在庫一覧と詳細画面では、グラム数に加えて「あと何杯」を表示します。1杯あたりの豆量をもとに杯数を算出し、一覧では残り杯数による並び替えもできます。

実装：[在庫一覧](src/features/home/HomePage.tsx) · [商品詳細](src/features/bag-detail/DetailPage.tsx) · [杯数の計算](src/lib/utils/coffee.ts)

### 商品の種類に応じたフォーム

商品登録では、通常商品とセット商品で入力項目を切り替えます。通常商品では袋重量、セット商品ではセット価格などを入力し、未入力の必須項目をフォーム上部に表示します。精製方法は選択肢に加えて手入力にも対応しています。

レイアウトは画面幅に応じて1列から2列に切り替わります。

実装：[登録フォーム](src/features/bag-new/components/BagFormGrid.tsx) · [入力検証](src/features/bag-new/utils/form-validation.ts)

### 抽出条件と在庫更新の扱い

抽出記録は専用画面で入力します。在庫を減らす場合は残量を超える豆量を制限し、記録の編集・削除時にも在庫への反映を扱います。

実装：[抽出記録画面](src/features/bag-detail/RecordExtractionPage.tsx) · [記録の編集・削除](src/features/bag-detail/DetailPage.tsx)

## 共通UIの設計と適用状況

### スタイルとコンポーネント

[共通スタイル](src/styles/globals.css)には、背景・文字・境界線・破壊的操作などの色、角丸、フォント、ページレイアウトを定義しています。

[Button](src/components/ui/button.tsx)は、用途とサイズをそれぞれ`variant`と`size`で指定する構成です。通常操作、削除操作、補助操作などの表現を共通化し、無効状態とキーボード操作時のフォーカス表示を定義しています。[Input](src/components/ui/input.tsx)にも、無効状態、フォーカス、`aria-invalid`に応じたスタイルがあります。

UIにはRadix UIのプリミティブを使用しています。

### 現在の適用範囲と改善候補

登録フォームには`input`や`select`へ直接スタイルを指定した箇所も残っています。今後は共通部品の適用範囲と利用ルールを整備していきます。

- フォーム部品の適用状況を整理し、既存の入力挙動を維持しながら段階的に共通化する。
- コンポーネントの用途、状態、使い分けを確認できるガイドを整備する。
- スクリーンリーダーでの実際の読み上げ、拡大時のレイアウト、画面幅ごとの操作性を実機で検証する。

## 改善事例

### オブジェクトと操作の対応を整える

コードレビューで、抽出記録の詳細にある編集ボタンの遷移先が未実装であること、消費済みの豆を「購入履歴」と表示していること、定期購入設定が在庫に混在すること、豆の削除に編集画面を経由する必要があることを確認しました。

既存のデータ構造を維持しながら、画面上の対象と操作の対応を次のように修正しました。

| 対象 | 変更前 | 変更後 |
| --- | --- | --- |
| 抽出記録 | 詳細からの編集先が未実装 | 編集ルートを追加し、豆の詳細と同じ編集フォームを使用。保存・キャンセル後は対象の記録詳細へ戻る |
| 消費済みの豆 | 「購入履歴」という名称 | 表示対象に合わせて「飲み切った豆」へ変更。在庫が空でもアクセス可能 |
| 定期購入設定 | 豆の在庫と同じ一覧・集計・抽出操作の対象 | 一覧内の別セクションへ分離し、在庫集計から除外。設定への抽出記録追加も禁止 |
| 豆・セットの削除 | 編集画面を経由 | 詳細から確認ダイアログを開いて削除。セットを削除しても中の豆と記録は保持 |

定期購入は設定として扱い、初回の豆は通常の在庫として別途登録することを登録画面に明示しています。既存設定に保存済みのデータは削除せず、過去の抽出記録は詳細から引き続き参照できます。

関連実装：[詳細と編集・削除](src/features/bag-detail/DetailPage.tsx) · [在庫と定期購入設定](src/features/home/HomePage.tsx) · [関連する豆を保持する削除処理](src/lib/delete-bag.ts)

回帰テストでは、編集の保存・キャンセル、残量を超える入力の拒否、削除の確認・失敗時の再試行、セット内の豆の保持、定期購入設定と在庫の表示分離を確認しました。これらの改善後の実機検証と、利用上の効果の測定は未確認です。

OOUIを意識した画面構成は自分で決め、AIによるレビューを依頼したうえで、OOUI・アクセシビリティの改善を進めました。修正コードと回帰テストの作成・実行はAIが行っています。

## 技術構成

| 領域 | 使用技術 |
| --- | --- |
| アプリケーション | Next.js 16 / App Router、React 19、TypeScript |
| UI | Tailwind CSS v4、Radix UI、class-variance-authority、Lucide |
| データ保存 | Dexie / IndexedDB |
| PWA | Web App Manifest、Service Worker |
| テスト | Jest、React Testing Library |

`src/app`がルーティング、`src/features`が機能別の画面、`src/components/ui`が共通UI部品を担います。データベース定義や計算処理は`src/lib`に配置しています。

豆と画像はブラウザ内のIndexedDBに保存します。[データベース定義](src/lib/db.ts)にはスキーマのバージョン管理と、既存データへのメタデータ追加処理があります。クラウド同期は未実装で、異なる端末・ブラウザ間でデータは共有されません。ブラウザのサイトデータを削除すると保存内容も失われます。

Service Workerには画像などのキャッシュとオフラインページへのフォールバックを実装しています。ただし、`/_next/`のリソースはネットワーク取得にしているため、完全なオフライン動作を保証する構成ではありません。詳細は[Service Worker](public/service-worker.js)を参照してください。

## ローカルで動かす

Node.jsとnpmを用意し、リポジトリのルートで実行してください。

```bash
npm ci
npm run dev
```

ブラウザで [http://localhost:3000](http://localhost:3000) を開きます。基本機能の利用に外部サービスのAPIキーは不要です。

```bash
# テスト
npm test

# カバレッジ
npm run test:coverage

# Lint
npm run lint

# 本番用ビルド・起動
npm run build
npm start
```
